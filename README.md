# Приоритизация обращений (lead scoring)

Решение задачи по ранжированию обращений (leads) на основе вероятности успешного целевого действия в течение 5 дней после назначения обращения в обработку.

## Постановка задачи

Одна строка в данных соответствует одному назначенному обращению в конкретный момент времени: не пользователь, не объявление, не дилер и не звонок сами по себе, а контекст вокруг факта назначения обращения в обработку.

Входные данные:

- `data/train.csv` - обучающая выборка с `target`;
- `data/test.csv` - тестовая выборка без `target`;
- `data/events.csv` - дополнительные события пользователей для feature engineering.

Целевая переменная: `target = 1`, если в течение 5 дней после назначения произошло успешное целевое действие, иначе `target = 0`.

Метрика качества: **Daily Average Precision** - AP считается отдельно для каждого дня (`assignment_date`), затем усредняется. Важно правильное ранжирование обращений именно внутри одних суток.

Формат ответа: файл с двумя колонками - `lead_id` и `score` (число от 0 до 1, чем выше, тем перспективнее обращение).

Ключевое ограничение: все признаки должны быть доступны на момент назначения обращения. При построении признаков из `events.csv` используются только события с `event_ts < assignment_ts`, поскольку в исторических данных встречаются события, произошедшие уже после назначения, и в production-скоринге такой информации быть не может.

Итоговая метрика: 0.70 на валидации, 0.67 на тестовой выборке.

## Структура решения (`solution.ipynb`)

Ноутбук устроен последовательно и состоит из следующих блоков.

### 1. Загрузка данных и разведывательный анализ (EDA)

- Проверка распределений категориальных признаков (`region`, `call_center`, `car_segment`, `lead_source`).
- Проверка на выбросы (boxplot, IQR) для цены, пробега, возраста авто, размера инвентаря продавца.
- Проверка на нарушение монотонности готовых оконных агрегатов (например, `item_views_1d > item_views_3d`) - таких строк оказалось довольно много, это учтено при построении признаков.
- Анализ `events.csv`: распределение числа событий на пользователя, распределение по типам событий, пересечение `user_id`/`lead_id` между `events` и `train`/`test`, распределение разницы во времени между событием и назначением.
- Проверка соответствия цены объявления в `train` и в `events` (расхождения есть, это учтено отдельным признаком).
- Анализ таргета: доля `target` в целом и по дням, зависимость от часа дня и дня недели, сравнение временных диапазонов `train` и `test`.

### 2. Feature engineering

Все признаки, построенные из `events.csv`, фильтруются по условию `event_ts < assignment_ts`, чтобы исключить утечку данных из будущего. Признаки собраны в несколько тематических блоков:

- **Аномалии оконных агрегатов** - флаг и счетчик нарушений монотонности между соседними временными окнами (1d/3d/7d/14d/30d/90d) для всех числовых агрегатов активности.
- **Признаки по событиям конкретного обращения** - временные лаги до последнего события и до последних "горячих" действий (звонок, чат, избранное), количество событий за последний час и за 6 часов, экспоненциально затухающий по времени скор активности (time decay), число уникальных цен и контекстов в истории, статистики позиции в выдаче (`src_slot`), счетчики и доли типов событий, отношение поисковых действий к просмотрам, расхождение цены в событиях и в момент назначения.
- **Признаки воронки и сессий** - глубина воронки (насколько "горячим" было максимальное действие), флаг достижения горячей стадии воронки, разбиение событий на сессии по паузам более 30 минут, число сессий.
- **Пользовательская история** - общее число событий пользователя до текущего назначения, число уникальных объявлений, число горячих действий, "возраст" пользователя на платформе, время с последнего действия, доля горячих действий в истории.
- **Признаки взаимодействий и цикличности** - произведения признаков (цена и недавняя активность, возраст аккаунта и глубина воронки, расхождение цены и попадание в горячую воронку, интенсивность сессий), синус/косинус кодирование часа и дня недели назначения, плотность событий пользователя.
- **Контекст платформы** - суммарное число событий на всей платформе за предыдущий полный час относительно момента назначения (показывает общую нагрузку - час пик или нет).

После построения признаков проверяется корреляция числовых признаков с таргетом.

### 3. Валидация

Используется временной сплит: 80% ранних дат обучающей выборки идут в train, 20% поздних дат - в valid. Такой подход ближе к реальному сценарию, чем случайное разбиение, так как тестовая выборка находится позже train по времени. Есть fallback на стратифицированный `train_test_split`, если даты недоступны.

Качество модели считается функцией `calculate_daily_ap`, которая повторяет боевую метрику: AP считается отдельно по каждой дате назначения, затем усредняется по всем датам.

### 4. Моделирование

- Категориальные признаки кодируются с помощью target encoding со сглаживанием (защита от переобучения на редких категориях), числовые - медианой для пропусков. Кодировщик реализован как `sklearn`-совместимый трансформер (`PipelineFeatureEngineer`), обучается только на train-части, без утечки из valid/test.
- Обучается ансамбль из трех бустингов: **CatBoost**, **LightGBM**, **XGBoost**.
- Гиперпараметры каждой модели подбираются отдельно с помощью **Optuna**.
- Финальный прогноз строится блендингом: предсказания трех базовых моделей на валидации используются как мета-признаки для мета-модели - логистической регрессии.

### 5. Формирование сабмита

Сырые вероятности переводятся в перцентили ранга внутри каждого дня (`assignment_date`), так как метрика Daily AP оценивает ранжирование обращений внутри суток, а не абсолютные значения вероятности. Результат сохраняется в `submission.csv` с колонками `lead_id` и `score`.

## Используемые библиотеки

- `pandas`, `numpy` - обработка данных;
- `matplotlib`, `seaborn` - визуализация;
- `scikit-learn` - метрики, сплиты, логистическая регрессия, базовые интерфейсы трансформеров;
- `catboost`, `lightgbm`, `xgboost` - базовые модели ансамбля;
- `optuna` - подбор гиперпараметров.

## Как воспроизвести

1. Положить `train.csv`, `test.csv`, `events.csv` в папку `data/` рядом с ноутбуком.
2. Установить зависимости:

   ```bash
   pip install pandas numpy scikit-learn catboost lightgbm xgboost optuna matplotlib seaborn
   ```

3. Выполнить `solution.ipynb` сверху вниз.
4. На выходе получится файл `submission.csv` с колонками `lead_id` и `score`.
